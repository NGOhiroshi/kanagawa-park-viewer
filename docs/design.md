# 神奈川公園ビューワー 設計書

> 神奈川県オープンデータを使った、子連れ世帯向け公園検索PWA。
> 「ブランコAND砂場」など**ニッチ条件のAND/OR検索**と**手軽さ**を売りに、既存の全国型サービスとは異なるポジションを取る。

最終更新: 2026-05-23

---

## 1. プロダクト方針

### 1.1 立ち位置

神奈川特化×即検索×ニッチ条件AND/OR検索を軸に、既存の全国型・SNS型公園サービスとは異なるポジションを取る。

- **エリア**: 神奈川特化（約8千件）
- **思想**: 検索ユーティリティ型（コミュニティ/SNS機能なし）
- **検索**: AND/OR切替＋詳細モード式エディタ
- **起動**: ログイン不要、即検索
- **配信**: PWA（インストール不要）
- **収益**: 非営利・個人プロジェクト

### 1.2 ユーザーストーリー（コア）

- 「近所でブランコと砂場と多目的トイレがある公園、現在地から近い順で見たい」
- 「ローラースライダー OR ふわふわドーム どっちかでもあれば子どもが喜ぶから、その条件で」
- 「広い芝生広場でピクニックしたい」

### 1.3 MVPスコープ

含める:
- ① 設備AND/OR検索 + 一覧
- ② マップビュー（クラスタリング）
- ③ 現在地から距離順ソート
- ④ 公園詳細（設備・住所・開園時間・関連リンク・Google Mapsへナビ）
- ⑤ PWA化（ホーム追加・オフライン動作）

含めない（意図的に）:
- ユーザー投稿・写真・レビュー・SNS機能（検索ユーティリティとしての差別化、運用負荷の回避）
- ログイン・サーバー認証（手軽さに反する）
- 全国展開（神奈川密度＝差別化の源泉）
- 広告・課金

## 2. 技術スタック

| レイヤ | 選択 | 理由 |
| --- | --- | --- |
| フレームワーク | Vite + React + TypeScript | 静的サイト化が容易、PWA化は `vite-plugin-pwa` で一行 |
| 地図 | MapLibre GL JS | OSS、APIキー不要 |
| 地図タイル | 国土地理院（地理院タイル） | 無料、個人利用は申請不要、出典明記必須 |
| 状態管理 | Zustand + URLクエリ | 検索条件をURL共有可能に＝「手軽さ」に寄与 |
| データ | クライアント全件JSON配信 | DB・APIサーバー不要、CDNキャッシュで爆速 |
| パッケージ管理 | pnpm | ディスク効率、Cloudflare Pages公式サポート |
| ホスティング | **Cloudflare Pages** | 帯域無制限・東京/大阪PoP・独自ドメイン無料・商用OK |

### 2.1 採用候補から落とした選択肢
- Vercel Hobby — 商用利用不可（規約） → 将来何かするかもしれないので除外
- Netlify — 日本のレイテンシ不安定
- Firebase Hosting — 帯域10GB/月の上限が厳しい
- GitHub Pages — キャッシュ制御が弱く、独自ドメインHTTPSが遅延
- Nominatim ジオコーディング — レート制限・商用利用注意 → 国土地理院を採用
- Google Maps Geocoding — 有料（無料枠あるがキー管理コスト）

## 3. データパイプライン

### 3.1 ソース

- **出典**: [神奈川県オープンデータポータル](https://www.pref.kanagawa.jp/docs/b8k/cnt/f536260/)
- **ファイル**: `data/raw/parks_raw_sjis.csv` (140007_park.csv)
- **文字コード**: Shift-JIS（注意：UTF-8で開くと文字化け）
- **件数**: 8,094件
- **更新**: 不定期。再取得時は `data/raw/` を差し替えて `pnpm build-data` を再実行

### 3.2 パイプライン構成

```
data/raw/parks_raw_sjis.csv  (Shift-JIS, 1.3MB)
  │
  ├─ scripts/parse-csv.ts  ──→  data/processed/parks.base.json  (UTF-8, 11MB, 構造化)
  │
  ├─ scripts/geocode.ts    ──→  data/processed/geocode_cache.json  (1.2MB)
  │                              ↑ レジューム可、失敗は geocode_failures.json に分離
  │
  └─ scripts/finalize.ts   ──→  public/parks.json  (864KB raw / 254KB gzip)
                                ↑ bit-pack＋tuple化＋座標5桁丸め
```

スキーマは `scripts/schema.ts` を**単一の正規ソース**として、フロントエンドもこれをimportする想定。

### 3.3 配信用JSON形式

```json
{
  "version": 1,
  "generatedAt": "2026-05-23T...",
  "facilityKeys": ["toilet", "accessibleToilet", "water", "swing", ...],
  "fieldOrder": ["id", "name", "address", "lat", "lng", "facilities", ...],
  "parks": [
    ["002654", "境川遊水地公園", "神奈川県横浜市泉区下飯田町5-5", 35.39020, 139.48207, 12345678, "総合公園", 2007, 261292, "...", "...", "...", "...", "..."]
  ]
}
```

- **設備フラグ**: 42ビットのbitmask（JS Number.MAX_SAFE_INTEGERは53bit、安全）
- **緯度経度**: 小数5桁（約1m精度）
- **タプル化**: キー名のコストを排除、gzipで重複しやすい

### 3.4 ジオコーディング戦略

- API: 国土地理院 [`AddressSearch`](https://msearch.gsi.go.jp/address-search/AddressSearch?q=...) （APIキー不要）
- 並列度: 5
- politeness: ワーカー毎50ms間隔
- **2段階フォールバック**: 完全住所 → ヒットなし時は番地を除去して再試行
- **レジューム**: 結果は逐次 `geocode_cache.json` に保存、再実行は未処理分のみ
- 成功率: 99.99% (8093/8094)。失敗1件は元データの住所が空（引地川緑地）

## 4. UI設計

### 4.1 画面構成（4画面のみ）

1. **トップ（マップ + クイックチップ）** — 起動即マップ。下部に主要チップ（ブランコ・砂場・トイレ・駐車場・水遊び）、上部にAND/ORトグル
2. **フィルタパネル**（ボトムシート） — 全42設備をカテゴリ別（遊具/設備/スポーツ/動物/飲食/その他/駐車場）に。「詳細モード」ボタンで式エディタへ
3. **公園詳細** — 設備アイコン一覧、住所、開園時間、Google Mapsへのナビリンク、関連リンク
4. **詳細モード（式エディタ）** — `(ブランコ AND 砂場) OR ローラースライダー` のような式をチップのD&D/タップで構築

### 4.2 AND/OR UI — 二段構え

| モード | UI | 想定ユーザー |
| --- | --- | --- |
| **デフォルト** | 画面上部に「AND ⇄ OR」トグル1つ | 大半のユーザー |
| **詳細モード** | 式エディタで `(A AND B) OR C` を構築 | パワーユーザー |

理由: シンプルな全体トグルだけだと表現力不足、最初から式エディタだと敷居が高い。両立で初心者にも上級者にも対応。

### 4.3 設備カテゴリ

```
基本    : トイレ, 多目的トイレ, 水飲み・手洗い
遊具    : ブランコ, すべり台, 砂場, ジャングルジム, 鉄棒, シーソー, ...
広場    : 芝生広場, 水遊び, ランニングコース
スポーツ: テニス, バスケット, 野球, フットサル, サッカー, スケート, プール, ...
動物    : ウサギ・モルモット, ハムスター, ひよこ, 馬・ポニー
飲食    : カフェ, 売店, 自動販売機, BBQ
その他  : ドッグラン, 喫煙所, イベント広場, 避難場所
駐車場  : 無料駐車場, 有料駐車場, 駐輪場
```

## 5. パフォーマンス設計

| 施策 | 効果 |
| --- | --- |
| Cloudflareによる brotli 自動圧縮 | 254KB → ~200KB級 |
| 設備フラグの bit packing | JSONサイズの大部分を削減（→ 254KB） |
| 緯度経度を小数5桁丸め | 数値文字数を削減 |
| Service Worker で `parks.json` を precache | 2回目以降オフライン動作・即起動 |
| 地図はクラスタリング（[supercluster](https://github.com/mapbox/supercluster)） | 8千ピン表示でも60fps維持 |
| 国土地理院タイルは外部直接配信 | 自前ホスティング不要 |
| 検索はクライアント側全件フィルタ | サーバーレス・オフライン可能 |

## 6. デプロイ

### 6.1 Cloudflare Pages

- **連携方法**: GitHub連携 → `main` push で自動デプロイ
- **ビルドコマンド**: `pnpm install && pnpm build`
- **出力ディレクトリ**: `dist/`
- **環境変数**: 不要（APIキー類は使わない）
- **ビルド分**: 500分/月の無料枠で十分

### 6.2 CI/CD方針

- ジオコーディングのバッチは**手元で実行**、結果（`public/parks.json`）をリポジトリにコミット → Cloudflare Pagesでは静的ビルドのみ
- 理由: 本番ビルドにAPI依存を持ち込まない、外部API障害でデプロイが落ちないようにする

### 6.3 国土地理院タイル利用について

- **個人プロジェクトは申請不要**
- **出典明記必須**: フッターに「地理院タイル」と表記
- 商用化する場合は別途確認

## 9. 既知のリスク・未決事項

| 項目 | リスク | 対応方針 |
| --- | --- | --- |
| 神奈川県データの更新頻度・形式変更 | カラム変更でパーサが壊れる | スキーマ検証を `parse-csv.ts` に追加（将来） |

| 詳細モードのUX | 式エディタは複雑になりがち | チップD&Dで「式を組まされている感」を消す |
| 神奈川県以外のユーザー | スコープ外 | MVPでは無視。要望次第で他県対応 |
